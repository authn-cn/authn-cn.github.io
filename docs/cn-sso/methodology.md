# 中国平台 API / SDK 企业集成评价方法

本章评价的对象不是厂商自身“怎么鉴权”，而是企业客户或外部系统接入厂商时，实际能获得什么 API、SDK、事件能力和交付保障。协议是否标准只是其中一项。

## 先按产品类型比较

本站收录的平台分为三组，组内结论可以直接比较，跨组分数只能用于观察“集成成熟度”，不能代替选型：

| 类型 | 平台 | 典型采购目标 |
|---|---|---|
| 企业协作开放平台 | 飞书、钉钉、企业微信 | 通讯录、消息、审批、文档、日历、客户联系与工作台集成 |
| C 端身份与渠道平台 | 微信开放平台 | 网站/App/公众号/小程序的微信登录和用户触达 |
| 内容与设备合作平台 | 喜马拉雅、QQ 音乐、网易云音乐 | 车机、IoT、App 中的内容、播放、会员和账号互通 |

## 统一评分维度

每项按 1–5 分评价。总分是加权结果，满分 100；它衡量的是**公开可验证的企业集成就绪度**，不是产品市场份额或终端体验。

| 维度 | 权重 | 统一检查项 |
|---|---:|---|
| 场景与企业适配 | 10% | 自建应用、第三方/商店应用、多租户、私有化或 OEM 场景是否清晰 |
| API 覆盖与可组合性 | 20% | 组织、消息、内容、审批、用户数据等核心资源是否可读写；分页、批量、幂等是否可用 |
| SDK 与开发工具 | 15% | 官方语言覆盖、类型定义、令牌维护、验签/解密、示例、调试台、版本发布 |
| 身份、权限与数据边界 | 15% | 应用身份/用户身份、细粒度 scope、字段权限、管理员授权、稳定用户标识 |
| 事件与数据同步 | 10% | Webhook/长连接、事件覆盖、重试、去重标识、补偿拉取和增量同步 |
| 运行与可观测性 | 10% | 限流说明、请求 ID、错误码、调用日志、告警、状态页、SLA/配额扩容 |
| 文档、测试与版本治理 | 10% | 文档公开性、更新时间、变更记录、沙箱/测试企业、废弃策略、兼容期 |
| 企业交付与合规 | 10% | 应用审核、权限审批、数据合规、合同/SLA、技术支持、商务依赖 |

### 分数含义

| 分数 | 含义 |
|---:|---|
| 5 | 能力完整，官方公开资料和工具可验证，可按常规企业工程流程落地 |
| 4 | 主体能力完整，但存在权限、产品版本、审核或局部私有协议约束 |
| 3 | 能完成目标场景，但需要较多适配或商务协作，关键治理信息不完整 |
| 2 | 能力窄、资料封闭或运行保障不透明，交付高度依赖厂商项目团队 |
| 1 | 未找到可生产使用的公开能力，或不适合该类企业场景 |

总分分级：A（85–100）、B（70–84）、C（55–69）、D（低于 55）。

## 证据等级与表述规则

| 等级 | 证据 | 文档中的写法 |
|---|---|---|
| A | 当前可访问的官方公开文档、官方 SDK 仓库、官方控制台说明 | 可写为“支持/限制为”，并附官方链接 |
| B | 厂商提供给合作方的 SDK 文档、合同附件或控制台内容，但公众无法访问 | 写明“依据合作方文档”，并要求项目启动时复核版本 |
| C | 售前口径、历史资料、社区资料或根据接口行为推断 | 只写“需确认/未公开”，不得写成平台承诺 |

以下内容若没有 A/B 级证据，一律不作肯定承诺：

- SLA、可用性数字、灾备等级和支持响应时限；
- 全量接口配额、突发流量策略和扩容方式；
- 数据驻留、删除证明、审计保留期；
- SDK 长期支持周期、废弃通知期；
- 未公开的账号、会员、版权或内容授权范围。

## 企业选型的最低验收清单

无论厂商得分高低，生产采购前都应让厂商或服务商书面确认：

1. 提供本项目将使用的 API、scope、字段权限、事件和 SDK 版本清单。
2. 给出测试租户/测试账号、生产配额、扩容流程与 429/重试策略。
3. 给出用户和资源 ID 的作用域、合并/离职/换绑规则。
4. 给出事件的至少一次投递语义、唯一事件 ID、重试窗口和补偿拉取方案。
5. 给出版本废弃通知期、变更日志渠道和紧急变更联系人。
6. 明确数据处理角色、敏感字段、跨境/驻留、删除和审计要求。
7. 对商务 SDK，必须把 API/SDK 清单、版本、SLA、支持时限写入合同附件。

> 评分核验日期：2026-07-27。平台能力会持续变化，具体项目仍应以控制台实际可申请权限和双方合同为准。
