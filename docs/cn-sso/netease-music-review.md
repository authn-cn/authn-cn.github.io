# 网易云音乐 OpenAPI 企业集成评价

> 使用[统一评价方法](./methodology.md)。本页依据仓库所引用的合作方“音乐 API 文档”和可访问的开放平台页面评价；大量细节不是稳定公开文档，按 B 级证据处理。

::: tip 结论
**64 / 100（C）**。合作方 OpenAPI 覆盖设备登录、用户资料、内容、播放、歌单与会员等场景，访问/刷新令牌和 RSA-SHA256 请求签名比单纯 SDK 账号回调更适合服务端集成。但官方文档公开可访问性、统一多语言 SDK、事件体系、调用日志、SLA 和版本治理证据不足，生产交付仍高度依赖项目接口人与合同。
:::

## 已确认的企业价值

现有合作方资料显示，平台以 `openapi.music.163.com` 提供设备扫码/H5 登录、访问与刷新令牌、用户资料以及音乐内容相关 API。RSA-SHA256 请求签名和时间戳校验可用于应用鉴别和防止陈旧请求；访问令牌与刷新令牌分离便于设备长期登录。

这些能力不等于标准 OIDC：`accessToken` 是资源访问凭据，用户 `id` 是平台字段，并没有可供外部系统离线验证的 `id_token`。企业应把平台用户 ID 映射为自己的内部账号，登录成功后只签发本企业的会话或令牌。

## 需要谨慎使用的协议细节

合作方文档中部分接口允许 GET/POST，并把 `appSecret`/`clientSecret` 列为请求参数。若密钥进入 URL，最常见风险是网关、代理、访问日志和 APM 记录完整查询串。不能因为还有 RSA 签名就认为传 secret 没有风险。

生产要求：

- 优先使用 POST 和 HTTPS；密钥只在服务端，所有日志对查询串和业务参数脱敏；
- 明确签名原文的规范化、字符集、参数排序、时钟偏差和重放窗口；
- 私钥放 KMS/HSM 或受控密钥服务，不随设备 SDK 分发；
- 轮换公钥/私钥时要求平台支持并行新旧密钥和回滚窗口。

## 企业风险与建议

1. **不要把合作方文档当长期版本承诺**：在合同附件列出 docId、API 路径、字段和版本，并约定变更通知期。
2. **要求官方 SDK/签名样例或建立自测向量**：对同一组参数固定签名结果，避免各语言排序和编码不一致。
3. **明确 ID 与账号生命周期**：用户合并、注销、未成年人账号、会员变化、设备换绑都要有处理规则。
4. **轮询登录要做退避**：按文档间隔轮询，处理等待、拒绝、过期和限流；不要无限固定频率请求。
5. **补齐可观测性**：保存接口路径、业务 code、subCode、耗时和脱敏后的请求摘要；要求平台提供可用于工单定位的请求标识。
6. **版权和会员能力合同化**：可播放、可缓存、音质、区域、终端、会员类型和内容下架处理不能只依赖接口字段。

## 已修正的旧结论

- “最接近标准”不是企业选型标准；令牌模型和 RSA 签名值得肯定，但 SDK、事件、文档和 SLA 同样重要。
- RSA-SHA256 请求签名不等于 JWS，也不能自动补齐 OIDC 身份语义。
- 现有 AT/RT 时长、错误码和具体端点属于合作方文档信息；上线前必须以当前版本复核，不作为永久公开承诺。
