# 微信开放平台 API / SDK 企业集成评价

> 使用[统一评价方法](./methodology.md)。微信个人账号适合 C 端登录与渠道连接，不是企业组织目录或员工身份源。评分按 C 端企业应用场景给出。

::: tip 结论
**68.5 / 100（C）**。微信网站/App/公众号/小程序登录拥有成熟入口和庞大生态，移动 OpenSDK、JS-SDK 和小程序运行时也很成熟。但不同产品线的应用、scope、令牌和 ID 不能混用；服务端登录 API 私有、缺少 OIDC 身份令牌；没有部门、雇佣状态或企业管理员生命周期。因此它适合 CIAM/用户登录，不适合代替企业 SSO。
:::

## 统一评分

| 维度 | 分数 | 企业判断 |
|---|---:|---|
| 场景与企业适配 | 3.0 | C 端网站/App/公众号/小程序适配强，企业组织场景不适用 |
| API 覆盖与可组合性 | 4.0 | 微信生态 API 广；单看登录，主要是授权、令牌和基础用户资料 |
| SDK 与开发工具 | 3.5 | 移动、网页、小程序 SDK 成熟；服务端身份 API 仍需私有适配 |
| 身份、权限与数据边界 | 3.0 | 授权 scope 和应用审核可用；跨应用 ID 条件复杂，无组织身份 |
| 事件与数据同步 | 3.0 | 公众号/小程序有回调，但登录自身无企业目录增量同步 |
| 运行与可观测性 | 3.0 | 错误码与配额可查，统一 SLA、请求追踪和标准错误语义不足 |
| 文档、测试与版本治理 | 3.5 | 各产品线文档完整，但入口分散、规则差异大 |
| 企业交付与合规 | 4.0 | 应用审核、隐私规范成熟；个人信息与跨应用归并需严格合规 |

## 正确的使用场景

| 需求 | 是否适合 |
|---|---|
| 个人用户登录网站或 App | 适合：网站应用或移动 OpenSDK |
| 公众号内网页授权 | 适合：区分 `snsapi_base` 与 `snsapi_userinfo` |
| 小程序建立自身登录态 | 适合：`wx.login` + 后端 `jscode2session` |
| 获取员工部门、工号、在职状态 | 不适合：应使用企业微信或企业 IdP |
| 员工离职后自动停用所有企业系统 | 不适合：个人微信没有企业雇佣生命周期 |

“微信用户已经实名认证”也不能推导出其是某企业员工，更不能把昵称、头像或手机号当企业账号权威属性。

## API / SDK 的企业工程评价

移动应用、网站应用、公众号和小程序是四套不同入口。它们可能共享开放平台的 `unionid` 关联能力，但前提是应用归属和绑定关系满足平台规则，且并非所有响应都必然返回 `unionid`。数据库应保存 `(appid, openid)` 原始键，并在实际获得 `unionid` 后建立可撤销的归并关系。

客户端 SDK 的价值是拉起微信、内嵌二维码、使用微信客户端能力和处理回调。服务端仍需要自行封装 code 换 token、刷新 token、读取用户信息、私有错误码和日志脱敏。微信登录没有标准 OIDC `id_token`；如果企业内部应用统一只接受 OIDC，应由自有身份网关完成账号映射并签发**本企业**的令牌，不能把微信 access token 冒充身份令牌。

## 主要风险与建议

1. **不要跨产品线复制代码和 token**：网站、移动应用、公众号、小程序的 AppID、scope 和端点分别管理。
2. **以复合键保存身份**：原始键是 `(appid, openid)`；`unionid` 只在满足条件且真实返回时用于关联。
3. **密钥和 code 只走后端**：AppSecret 不进入客户端、URL 日志、APM 标签或错误上报；对敏感查询参数脱敏。
4. **校验 `state` 并限制回调地址**：防止登录 CSRF 和账号错误绑定；移动端同时验证应用回跳。
5. **小程序登录与用户资料授权分开**：`wx.login` 建立平台身份不代表用户已同意提供头像、昵称、手机号等额外资料。
6. **准备解绑和账号合并流程**：用户可能撤销授权、换绑或在多个微信应用形成多个 `openid`，不可只做首次绑定。
7. **企业员工场景改用企业身份**：需要部门、职位、离职回收时，使用企业微信 `(corpId, userid)` 或企业 IdP。

## 已修正的旧结论

- 微信不是企业 SSO 平台；仅比较它和 OIDC 的协议差距会掩盖“C 端身份”和“企业员工身份”的根本区别。
- `wx.login` 是小程序获取临时 code 的平台机制，但不等同于用户同意提供所有个人资料；应按具体数据逐项授权。
- `unionid` 不是无条件存在的全局用户 ID，必须保留 AppID/OpenID 作用域和绑定条件。
